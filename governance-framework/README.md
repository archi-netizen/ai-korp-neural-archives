# Governance Framework

This folder documents the AI-KORP governance framework — the conceptual 
and regulatory layer that sits above the technical pipeline documented in 
`neural-asset-archives/`.

The framework addresses a prior question to capability: before asking what 
a generative or classification AI system can produce, it asks what conditions 
must be satisfied before that output is treated as design or planning authority.

---

## The AI-KORP Framework

AI-KORP organises generative and classification AI tools along two axes:

### Basket Axis — Domain of Application

| Basket | Symbol | Scope |
| :--- | :---: | :--- |
| Creative | 🎨 | Visual generation, brand design, rendering, illustration |
| Spatial | 📐 | Architectural design, urban modelling, spatial analysis |
| Intellectual | 🧠 | Research synthesis, knowledge extraction, design reasoning |
| Process | ⚙️ | Workflow automation, file management, documentation |

### Ripeness Axis — Governance Maturity

| Level | Symbol | Condition | Design Use Permitted |
| :--- | :---: | :--- | :---: |
| Sourcing | ○ | Asset ingested, provenance unverified | No |
| Sorting | ◐ | Classified, human review pending | No |
| Stored | ● | Verified, disclosed, cleared | Yes |

No output moves from Sorting to Stored without explicit human-in-the-loop 
review and disclosure of data provenance.

---

## Regulatory Alignment

The framework is designed in alignment with the EU AI Act 
(Regulation EU 2024/1689, in force 1 August 2024):

### Article 4 — AI Literacy
Providers and deployers of AI systems must ensure their staff have 
sufficient AI literacy to operate systems responsibly.

**AI-KORP response:** The Basket axis operationalises literacy requirements 
at practitioner level. Knowing which basket a tool belongs to, and at what 
Ripeness level its outputs sit, constitutes the minimum literacy threshold 
for responsible use in AEC and brand design practice.

### Article 50 — Transparency and Disclosure
Certain AI-generated content must be disclosed as such to end users.

**AI-KORP response:** The Ripeness axis operationalises disclosure 
requirements. A Stored ● classification confirms that the output has been 
reviewed and its AI-generated status is disclosed. A Sorting ◐ 
classification flags that disclosure conditions have not yet been met.

### Urban-Scale Extension
At urban scale, Article 50-style disclosure needs an equivalent mechanism 
for generative masterplans, streetscape renderings, and urban visualisations 
that reproduce recognisable trade dress or branded infrastructure patterns. 
The brand-architecture fusion typology documented in `urban-scale-evidence/` 
defines what that disclosure must cover.

## Application to Generative Urbanism

The governance question scales from tool to city:

| Scale | Governance Question | AI-KORP Response |
| :--- | :--- | :--- |
| Tool | Is this output verified and disclosed? | Ripeness axis |
| Building | Does this output reproduce brand signals? | Neural Asset Archives pipeline |
| City | Does the training corpus contain ungoverned brand-architecture fusion? | Urban-Scale Evidence typology |
| Urban system | Are disclosure and sovereignty conditions coordinated across actors? | Ripeness at Scale — proposed research direction |
